## Notes

- **Update URL.** `src/misc/update.c` fetches a status file from a fixed URL and appends the platform suffix (`-win-x64` on this fork). With GitHub Releases the "latest" redirect serves assets by name, so the status file and its detached signature are published as release assets and fetched as `<base>/status-win-x64` and `<base>/status-win-x64.asc` (the asset names are produced by `extras/redesign/make-status.sh` in Task 14). The base above never changes between releases; the asset contents do.
- **Product name and upstream.** "VLC" and the cone are VideoLAN trademarks, so the fork ships as **Vireo** with its own icon (Task 13b renamed it from "VLC Reborn", which contained the word VLC). The product says "built on VLC media player" and is not affiliated with VideoLAN: About says so and links to VLC, VideoLAN and the source; the exe and plugin version resources and the installers carry the same line. The word VLC remains where it is a technical fact: the `vlc-win64` output folder, plugin file names (`libvlc*.dll`), the `vlc://` URL scheme and command-line options.
- **Applied (Task 13 and 13b).** `meson_options.txt` options `redesign_product_name` (default `Vireo`) and `redesign_release_version` (default `0.1.0`) reach the code as `-DREDESIGN_PRODUCT_NAME` / `-DREDESIGN_RELEASE_VERSION` through `qt_cppargs` (the qt plugin) and `redesign_branding_cppargs` (unit tests), both set in `modules/gui/qt/redesign/meson.build`; the Windows resources (`bin/vlc_win32_rc.rc.in`, `modules/module.rc.in`) get them from `rc_conf` in the top `meson.build`, the NSIS script from `nsi_conf`. `redesign/cpp/branding.hpp` has `productName()`, `productWebsite()`, `releaseVersion()`, `versionTitle()` ("Vireo 0.1.0", plus " (build N)" for a numbered release) and `builtOnLine()`; `redesign/cpp/brandicon.hpp` has `appIcon()` (the PNG set in the redesign Qt resources: window, taskbar, tray, About, update pane). QML reads `MainCtx.productName`. Everything is gated by `qt-redesign`: stock mode keeps "VLC media player" and the cone.
- **Windows packaging (Task 13b, fix round 1).** The launcher is `vireo.exe` (the Linux test build keeps `bin/vlc`, which the test scripts use); icon `vireo.ico`; manifest identity `Vireo.Player`; one-instance IPC window `Vireo ipc <version>` (so it never talks to a stock VLC).
  - **Own per-user folder.** Configuration, user data and cache live in `%APPDATA%\vireo` (meson option `redesign_user_dir`, default `vireo`; `src/win32/dirs.c`, `src/win32/dirs-uap.c`, `bin/winvlc.c` crash-dump path, the Qt settings `vireo\vireo-qt-interface.ini` through `redesign/cpp/settingsfile.hpp`). Vireo never reads, writes, resets or deletes a stock VLC's `%APPDATA%\vlc`. Portable mode (a `portable` folder next to `vireo.exe`) works as before. There is no migration from `%APPDATA%\vlc`: Vireo is pre-release. `--reset-config` (the "reset preferences" shortcut) and the installer and uninstaller section "Delete preferences and cache" (`delprefs` in `NSIS/helpers/utils.nsh`) touch only this folder and `HKCU\Software\Vireo`. Setting the option to `vlc` gives upstream's shared folder back.
  - **Registry names of the application itself.** Preferences > Set associations (`simple_preferences.cpp`) opens the Windows Default Programs entry `Vireo`, and its fallback dialog writes the ProgIDs `Vireo<ext>` and the backup value `Vireo.backup` and takes the executable from `HKLM\Software\Microsoft\Windows\CurrentVersion\App Paths\vireo.exe`; the interface language is `HKCU\Software\Vireo\Lang` (`simple_preferences.cpp`, `bin/winvlc.c`; "Reset preferences" deletes only that key). Nothing of Vireo reads or writes `Software\VideoLAN` or a `VLC*` name any more.
  - **NSIS.** Install dir `Program Files\Vireo`, own key `HKLM\Software\Vireo`, uninstall entry `Uninstall\Vireo`, Start menu folder `Vireo`, installer `vireo-<release version>-win64.exe`, a new `PRODUCT_ID`, display version, installer file name and upgrade check use `redesign_release_version`. ProgIDs `Vireo.*` and `Vireo<ext>` in HKCR, `Applications\vireo.exe`, `App Paths\vireo.exe`, `Software\Clients\Media\Vireo`, the `Software\RegisteredApplications` value `Vireo`, `PlayWithVireo` / `AddToPlaylistVireo` verbs, the AutoplayHandlers; the Mozilla plugin key is gone (the plugin does not exist). Install and uninstall never read, write or delete `Software\VideoLAN`.
  - **Installer content (fix round 1).** `README.txt` and `RELEASE-NOTES.txt` are Vireo's own (`extras/package/win32/README.txt`, `RELEASE-NOTES.txt`; the Start menu "Release Notes" link opens the latter; edit them for each release). VLC's authors and thanks files stay for the GPL credit as `VLC-AUTHORS.txt` and `VLC-THANKS.txt`; `COPYING.txt` is the licence page; `Inter-OFL.txt` is the font licence. VLC's `NEWS` is not shipped. The Documentation and New Skins internet shortcuts and the "skinned" Start menu entry are gone (the website link is the project's). All installer wording (finish page, components, descriptions, uninstaller, MSI) says Vireo; VLC and VideoLAN appear only in the "built on VLC media player" credit.
  - **Installer languages.** All 53 NSIS language files (`languages/*Extra.nsh`) had "VLC media player" / "VLC" replaced by "Vireo" mechanically, and "VideoLAN" was removed from the website link text (Vireo is not made by VideoLAN). Gender and case endings in some languages (for example German "den Vireo") are not grammatically checked: **OWNER:** have the languages you ship reviewed, or limit the installer languages to the ones that were.
  - **Building the NSIS installer.** `bash extras/redesign/dev-build.sh --installer` builds `build-win64/installer/vireo-<release version>-win64.exe` in the win64 container (the 32-bit `nsProcess.dll` helper is built with the image's i686 MinGW-w64 gcc, `NSIS/meson.build`). See building.md. MSI: new UpgradeCode and component GUIDs, `Software\Vireo`, no VideoLAN folder or website shortcut, `vireo-<release version>-win64.msi`; there is no WiX in the image, so the MSI is **not built or tested** (**OWNER**).
  - **Not done / OWNER:** the installers were not run or installed on a Windows machine by this task, so the installer pages, Start menu and Apps & Features names need the check listed in the task report.
- **Name clearance.** OWNER: a formal trademark search for "Vireo" (and the icon) is pending; this task did not do one. Until it is done the name is provisional.
- **Settings of an earlier build.** The seeded control-bar profile was renamed from "VLC Reborn" to "Vireo" (`redesign/cpp/rebornprofile.cpp`) without a migration; a settings file of a development build keeps its old profile and the seeding flag, so the new default is not added to it. Harmless before the first release (such a file lives in the old `%APPDATA%\vlc`, which Vireo no longer reads).
- **Icons.** Generated, not hand-edited: `bash extras/redesign/make-icons.sh` (needs the Linux test container) renders the SVG master with Qt Svg, writes every file through a temporary name and validates it (PNG signature and size, every `.ico` entry decoded, 16-24 px from `vireo-icon-small.svg`, every BMP decoded again as B,G,R with a pixel of the mark required to read exactly #D37918; `extras/redesign/check_brand_bmp.py` does the same without Qt, also on bitmaps extracted from a built installer). The MSI banner stays single-resolution (Windows Installer scales it; the MSI is not shipped yet). The old VLC files (`share/icons/vlc.ico`, `NSIS/vlc_branding.bmp`, `msi/bannrbmp.bmp`) stay in the tree for the autotools packaging and upstream merges but nothing in the meson build uses them. The `share/icons/*` PNG/SVG set for Linux desktops is not replaced (the fork is Windows-only). **OWNER:** review the artwork before the first public release.
- **GPG key and update channel (Task 14, done).** The owner generated the dedicated signing key (DSA 2048, key ID above); its private part exists only in the owner's keyring and as the GitHub secrets `UPDATE_GPG_KEY` (armored private key) and `UPDATE_GPG_PASSPHRASE`. `include/vlc_pgpkey.h` embeds the public key and **replaces** VideoLAN's: the fork never trusts VideoLAN's update feed, and VideoLAN's key does not vouch for ours (`videolan_public_key` / `videolan_public_key_longid` keep their upstream names). The updater contacts no VideoLAN host: upstream's `download_key()` (fetch of an unknown signer's key from download.videolan.org) is removed and a status file signed by any other key is refused ("Status file signed by an unknown key"). The signature is fetched next to the platform status file (`<base>/status-win-x64.asc`). `extras/redesign/check-update-urls.py` (meson test `test_qt_update_channel_urls`) fails the build tests if a VideoLAN update host appears in the sources or in libvlccore, or the status file and signature URLs diverge; `test_qt_update_versions_{dev,n3,n7}` run `update_NeedUpgrade()` from `update.c` for a development build and numbered releases in the default `linux-tests.sh` gate. The header is generated, not hand-edited: `extras/redesign/pgpkey-to-header.sh` (`--check` compares) reads `docs/redesign/reborn-update-public.asc`, rejects a key `src/misc/update_crypto.c` cannot verify (not v4, not DSA <= 3072/q <= 256 bits or RSA <= 4096, expired, revoked, secret) and writes the long id and the armored text. `src/misc/update.c` reads the status file from the `UPDATE_VLC_STATUS_URL` = meson option `redesign_update_url` (default: the base above + `/status`; the platform suffix `-win-x64` and `.asc` are appended as before; `config.h` `REDESIGN_UPDATE_URL`), so a test build can point at the download URL of a test release: `-Dredesign_update_url=https://github.com/<owner>/<repo>/releases/download/<tag>/status`. Version: meson option `redesign_build_number` N (default 0 = development build) makes the version `4.0.0.N` (`config.h` `REDESIGN_BUILD_NUMBER`, added to `PACKAGE_VERSION_EXTRA` by `update_NeedUpgrade()` to compare with line 1 of the status file, and added to `VERSION_EXTRA`, the Windows file version). `PACKAGE_VERSION_EXTRA` stays 0 on purpose (`lib/core.c` asserts it equals `LIBVLC_VERSION_EXTRA` of the installed libvlc header). With N > 0 the build also stops being a `-dev` build for the updater (`PACKAGE_VERSION_DEV` empty): upstream's rule "a -dev build always offers the same version again" would otherwise report an update for the version already installed. Release builds must pass `-Dredesign_build_number=N` with N higher than the previous release; `-Dupdate-check=enabled` is already part of the win64 build (`extras/package/win32/build.sh`). `extras/redesign/make-status.sh <N> <installer_url> <notes_file> <out_dir> [installer]` writes `status-win-x64` (+ `.asc`) and the installer's `.asc`; it needs `UPDATE_GPG_KEY` / `UPDATE_GPG_PASSPHRASE` in the environment, imports the key into a temporary `GNUPGHOME`, refuses to sign with any key but the embedded one and verifies every signature it makes. Upload `status-win-x64`, `status-win-x64.asc`, the installer and `<installer>.asc` as assets of the release (Task 15). `test_qt_update_channel` (`bash extras/redesign/linux-tests.sh test_qt_update_channel`) runs the real verifier against a status file and an installer signed by throwaway keys (accepted; one changed byte, truncation, another key's signature rejected), checks the embedded fingerprint and that the status URL is not a VideoLAN one. **OWNER / Task 15 (first release candidate):** the real key cannot sign in a test, so on the first rc (1) run make-status.sh with the real secrets, (2) install a build made with `-Dredesign_build_number=1`, publish N=2 and run Help > Check for Updates: it must offer 4.0.0.2 from the fork URL and `Status file authenticated` appears in the log; a status file with one byte changed must report a failure and offer nothing; (3) the installer download must verify (`<installer>.asc` next to it). GitHub serves release assets through a redirect (`objects.githubusercontent.com`): check on the rc that VLC's HTTP access follows it (the status and installer downloads rely on it).

### Rotating the update key

Needed when the passphrase or key leaks, or the key is replaced. Old installs only trust the key embedded in their binary, so a rotation takes two releases.

1. Generate the new key: `gpg --quick-gen-key "VLC Reborn Updates <email>" dsa2048 sign never` (DSA 2048 / q 256 is verified by `update_crypto.c`; RSA <= 4096 works too; ECC keys and version 5 keys do not).
2. Export the public key to `docs/redesign/reborn-update-public.asc` (`gpg --armor --export <id> > ...`, no secret) and run `bash extras/redesign/pgpkey-to-header.sh` to regenerate `include/vlc_pgpkey.h`; update the key row above (ID, fingerprint, uid) and the fingerprint constants in `modules/gui/qt/tests/test_update_channel.c` (`test_embedded_key`). `bash extras/redesign/linux-tests.sh test_qt_update_channel` must pass.
3. Replace the GitHub secrets `UPDATE_GPG_KEY` and `UPDATE_GPG_PASSPHRASE`. `make-status.sh` refuses to sign with a key that is not the one in the `.asc`, so do both in the same change.
4. **Transition.** A build that still embeds the old key rejects a status file signed with the new one. So the release that carries the new key (N) must still have its status file and installer signed with the **old** key (the old install checks them, installs N, which now trusts the new key); sign the following release (N+1) with the new key. Run `make-status.sh` for release N with the old secrets and `REBORN_UPDATE_PUBKEY` pointing at the old public key file, then remove the old secrets. If the old key is lost or leaked there is no in-app path: users must install N by hand.
