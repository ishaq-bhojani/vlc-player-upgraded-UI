## Notes

- **Update URL.** `src/misc/update.c` fetches a status file from a fixed URL and appends the platform suffix (`-win-x64` on this fork). With GitHub Releases the "latest" redirect serves assets by name, so the status file and its detached signature are published as release assets and fetched as `<base>/status-win-x64` and `<base>/status-win-x64.asc` (the asset names are produced by `extras/redesign/make-status.sh` in Task 14). The base above never changes between releases; the asset contents do.
- **Product name and upstream.** Spec section 7 says "VLC" and the cone are VideoLAN trademarks and that the fork ships under its own product name and icon ("*Name* built on VLC"). The chosen name "VLC Reborn" still contains the word VLC, and the Figma frames show the cone in the title bar. Both need an owner decision (rename, or obtain VideoLAN's permission) before the first public release. About must say the product is built on VLC and link to the source.
- **Applied by Task 13.** `meson_options.txt` option `redesign_product_name` (default `VLC Reborn`) is passed as `-DREDESIGN_PRODUCT_NAME` through `qt_cppargs` (the qt plugin) and `redesign_branding_cppargs` (unit tests), both set in `modules/gui/qt/redesign/meson.build`; `redesign/cpp/branding.hpp` has `redesign::productName()` and `productWebsite()`. QML reads `MainCtx.productName`. Everything is gated by `qt-redesign`: stock mode keeps "VLC media player". NSIS: `PRODUCT_NAME/GROUP/PUBLISHER/WEB_SITE`, install dir `Program Files\VLC Reborn`, English installer strings. The installer uses its own key `HKLM\Software\VLC Reborn` (InstallDir, Version, language) and never reads, writes or deletes `Software\VideoLAN`, so it coexists with a stock VLC install; its uninstall entry is `Uninstall\VLC Reborn`. At run time only `HKCU\Software\VideoLAN\VLC\Lang` (language chosen in Preferences; `bin/winvlc.c`, `simple_preferences.cpp`) is read, and nothing reads the HKLM keys. **ProgIDs/associations still use VLC names; must be separated before a public release.** Stock-VLC names the installer still writes and the uninstaller still deletes (so installing or removing VLC Reborn changes or removes a stock VLC's entries): the `VLC.*` ProgIDs in HKCR (`VLC.MediaFile`, `VLC.DVDMovie`, `VLC.CDAudio`, `VLC.VCDMovie`, `VLC.SVCDMovie`, `VLC.OPENFolder`, `VLC.Bluray`) and the per-extension associations, the AutoplayHandlers (`VLCPlay*OnArrival`, with their `EventHandlers` values), `HKCR Applications\vlc.exe`, `HKLM ...\App Paths\vlc.exe`, `HKLM Software\Clients\Media\VLC` and the `Software\RegisteredApplications` value `VLC`, `HKCR AudioCD\shell\PlayWithVLC` and `DVD\shell\PlayWithVLC`, and `SOFTWARE\MozillaPlugins\@videolan.org/vlc,version=...`. Also still stock: the MSI (`extras/package/win32/msi/product.wxs` reads `HKLM Software\VideoLAN\VLC` `InstallDir`, creates and removes that key, and uses the `VideoLAN` folder and website shortcut) and the manifest identity `VideoLAN.VLC` (`extras/package/win32/vlc.exe.manifest.in:6`). All of these must be separated before a public release. **Not done / OWNER:** the installer was not built or installed (no VM; NSIS is disabled in the win64 build), so the installer check, Start menu and Apps & Features names are pending; the NSIS language files of the other 30+ languages and the exe resource strings (`bin/vlc_win32_rc.rc.in`, `modules/module.rc.in`) still say "VLC media player"; the Start menu folder is `${PRODUCT_PUBLISHER}` ("VLC Reborn contributors").
- **Icon files.** Nothing was supplied. Until the owner provides the files, Task 13 keeps the upstream icon, and the `OWNER:` marker above blocks the release workflow (Task 15) from claiming branding is done. **OWNER: replace icons** (`share/icons/vlc.ico`, the `share/icons/*` PNG/ICO set, `extras/package/win32/NSIS/vlc_branding.bmp`): the VLC cone is a VideoLAN trademark, and Task 13 left every icon file untouched.
- **GPG key and update channel (Task 14, done).** The owner generated the dedicated signing key (DSA 2048, key ID above); its private part exists only in the owner's keyring and as the GitHub secrets `UPDATE_GPG_KEY` (armored private key) and `UPDATE_GPG_PASSPHRASE`. `include/vlc_pgpkey.h` embeds the public key and **replaces** VideoLAN's: the fork never trusts VideoLAN's update feed, and VideoLAN's key does not vouch for ours (`videolan_public_key` / `videolan_public_key_longid` keep their upstream names). The header is generated, not hand-edited: `extras/redesign/pgpkey-to-header.sh` (`--check` compares) reads `docs/redesign/reborn-update-public.asc`, rejects a key `src/misc/update_crypto.c` cannot verify (not v4, not DSA <= 3072/q <= 256 bits or RSA <= 4096, expired, revoked, secret) and writes the long id and the armored text. `src/misc/update.c` reads the status file from the `UPDATE_VLC_STATUS_URL` = meson option `redesign_update_url` (default: the base above + `/status`; the platform suffix `-win-x64` and `.asc` are appended as before; `config.h` `REDESIGN_UPDATE_URL`), so a test build can point at the download URL of a test release: `-Dredesign_update_url=https://github.com/<owner>/<repo>/releases/download/<tag>/status`. Version: meson option `redesign_build_number` N (default 0 = development build) makes the version `4.0.0.N` (`config.h` `REDESIGN_BUILD_NUMBER`, added to `PACKAGE_VERSION_EXTRA` by `update_NeedUpgrade()` to compare with line 1 of the status file, and added to `VERSION_EXTRA`, the Windows file version). `PACKAGE_VERSION_EXTRA` stays 0 on purpose (`lib/core.c` asserts it equals `LIBVLC_VERSION_EXTRA` of the installed libvlc header). With N > 0 the build also stops being a `-dev` build for the updater (`PACKAGE_VERSION_DEV` empty): upstream's rule "a -dev build always offers the same version again" would otherwise report an update for the version already installed. Release builds must pass `-Dredesign_build_number=N` with N higher than the previous release; `-Dupdate-check=enabled` is already part of the win64 build (`extras/package/win32/build.sh`). `extras/redesign/make-status.sh <N> <installer_url> <notes_file> <out_dir> [installer]` writes `status-win-x64` (+ `.asc`) and the installer's `.asc`; it needs `UPDATE_GPG_KEY` / `UPDATE_GPG_PASSPHRASE` in the environment, imports the key into a temporary `GNUPGHOME`, refuses to sign with any key but the embedded one and verifies every signature it makes. Upload `status-win-x64`, `status-win-x64.asc`, the installer and `<installer>.asc` as assets of the release (Task 15). `test_qt_update_channel` (`bash extras/redesign/linux-tests.sh test_qt_update_channel`) runs the real verifier against a status file and an installer signed by throwaway keys (accepted; one changed byte, truncation, another key's signature rejected), checks the embedded fingerprint and that the status URL is not a VideoLAN one. **OWNER / Task 15 (first release candidate):** the real key cannot sign in a test, so on the first rc (1) run make-status.sh with the real secrets, (2) install a build made with `-Dredesign_build_number=1`, publish N=2 and run Help > Check for Updates: it must offer 4.0.0.2 from the fork URL and `Status file authenticated` appears in the log; a status file with one byte changed must report a failure and offer nothing; (3) the installer download must verify (`<installer>.asc` next to it). GitHub serves release assets through a redirect (`objects.githubusercontent.com`): check on the rc that VLC's HTTP access follows it (the status and installer downloads rely on it).

### Rotating the update key

Needed when the passphrase or key leaks, or the key is replaced. Old installs only trust the key embedded in their binary, so a rotation takes two releases.

1. Generate the new key: `gpg --quick-gen-key "VLC Reborn Updates <email>" dsa2048 sign never` (DSA 2048 / q 256 is verified by `update_crypto.c`; RSA <= 4096 works too; ECC keys and version 5 keys do not).
2. Export the public key to `docs/redesign/reborn-update-public.asc` (`gpg --armor --export <id> > ...`, no secret) and run `bash extras/redesign/pgpkey-to-header.sh` to regenerate `include/vlc_pgpkey.h`; update the key row above (ID, fingerprint, uid) and the fingerprint constants in `modules/gui/qt/tests/test_update_channel.c` (`test_embedded_key`). `bash extras/redesign/linux-tests.sh test_qt_update_channel` must pass.
3. Replace the GitHub secrets `UPDATE_GPG_KEY` and `UPDATE_GPG_PASSPHRASE`. `make-status.sh` refuses to sign with a key that is not the one in the `.asc`, so do both in the same change.
4. **Transition.** A build that still embeds the old key rejects a status file signed with the new one. So the release that carries the new key (N) must still have its status file and installer signed with the **old** key (the old install checks them, installs N, which now trusts the new key); sign the following release (N+1) with the new key. Run `make-status.sh` for release N with the old secrets and `REBORN_UPDATE_PUBKEY` pointing at the old public key file, then remove the old secrets. If the old key is lost or leaked there is no in-app path: users must install N by hand.
